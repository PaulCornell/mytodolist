mytodolist

A simple to-do list app: a small local Node.js + Express server backed by a SQLite file, with a plain TypeScript browser client. Everything stays on your machine.

GitHub repo Features Quick start Architecture API Data model Testing Project layout Troubleshooting

Features

  • Add, edit, complete and delete tasks.
  • Filter the list by all, active or completed tasks, with a count of tasks remaining.
  • Clear all completed tasks in one action.
  • Tasks persist in a local SQLite database (todos.db) across restarts and devices that reach the server.
  • Only one runtime dependency (express); the database is Node's built-in node:sqlite.

Quick start

This page is hosted statically; the app itself runs locally. Clone it first: git clone https://github.com/PaulCornell/mytodolist.git && cd mytodolist.

Requires Node.js 22.18 or newer (for node:sqlite and native TypeScript execution).

npm install
npm start

Then open http://localhost:3000. npm start first compiles the client (prestart runs npm run build), then launches the server. Stop it with Ctrl+C; your tasks remain in todos.db.

ScriptWhat it does
npm startBuilds the client, then runs src/server.ts on port 3000.
npm run buildCompiles client/script.ts to public/script.js.

npm testAPI tests with Node's built-in test runner.
npm run test:e2ePlaywright browser tests.

Architecture

Three small layers:

  • Browser client — client/script.ts (compiled to public/script.js) renders the list, handles filters and calls the REST API with fetch. Static assets (index.html, style.css) live in public/.
  • Express app — src/app.ts serves public/ and exposes a JSON API under /api/tasks. It is exported without listening so tests can use it directly.
  • SQLite — src/db.ts opens the database (path from DB_PATH, default todos.db in the project root; :memory: for tests) and creates the table if needed.

src/server.ts is the entry point that starts the app listening.

API

All endpoints exchange JSON. A task looks like { "id": 1, "text": "Buy milk", "completed": false }.

Method & pathDescriptionResponses
GET /api/tasksList all tasks ordered by id.200 with an array
POST /api/tasksCreate a task. Body: { "text": string } (trimmed, must be non-empty).201 with the task; 400 if text is missing
PATCH /api/tasks/:idUpdate text and/or completed (must be a boolean).200 with the task; 400 invalid input; 404 unknown id
DELETE /api/tasks/completedDelete every completed task.204
DELETE /api/tasks/:idDelete one task.204
curl -X POST localhost:3000/api/tasks \
  -H 'Content-Type: application/json' \
  -d '{"text":"Write docs"}'

Data model

CREATE TABLE tasks (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  text       TEXT NOT NULL,
  completed  INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

The API converts the integer completed column to a boolean.

Testing

  • API tests (test/api.test.ts) run against an in-memory database, so they never touch todos.db.
  • Browser tests (e2e/todo.spec.ts) use Playwright and Chromium against a separate server on port 3100, also with an in-memory database. First run: npx playwright install chromium.

Troubleshooting

If npm start fails with EADDRINUSE, a previous server is still running on port 3000.

# macOS / Linux
lsof -ti :3000 | xargs kill

On Windows, find the PID with netstat -ano | findstr :3000, then run taskkill /PID <pid> /F.
